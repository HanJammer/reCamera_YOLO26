## `yolo26n.onnx`

Local file size: about 9.5 MiB.

ONNX metadata:

- IR version: `7`
- Opset: `ai.onnx:12`
- Input: `images [1,3,640,640]`
- Graph output: `output0 [1,300,6]`

The graph contains final TopK/Gather-style postprocessing and emits a compact 300-row detection output. However, it also contains internal YOLO26 detection head tensors that can be used as `model_transform --output_names` equivalents to Seeed's YOLO11 hardcoded list.

Derived YOLO26 detection pre-head outputs:

```text
/model.23/one2one_cv2.0/one2one_cv2.0.2/Conv_output_0
/model.23/one2one_cv3.0/one2one_cv3.0.2/Conv_output_0
/model.23/one2one_cv2.1/one2one_cv2.1.2/Conv_output_0
/model.23/one2one_cv3.1/one2one_cv3.1.2/Conv_output_0
/model.23/one2one_cv2.2/one2one_cv2.2.2/Conv_output_0
/model.23/one2one_cv3.2/one2one_cv3.2.2/Conv_output_0
```

These are the YOLO26 equivalent of the Seeed YOLO11 wiki names:

```text
/model.23/cv2.0/cv2.0.2/Conv_output_0
/model.23/cv3.0/cv3.0.2/Conv_output_0
...
```

So the immediate reported conversion failure is explained: the Seeed command used YOLO11 names, while this YOLO26 graph uses `one2one_cv*` names.

## Candidate `model_transform` command for detection

Generated by:

```bash
python tools/make_recamera_transform_cmd.py models/yolo26n.onnx \
  --model-name yolo26n \
  --test-input /app/default_dataset/000000179487.jpg \
  --mlir /tmp/onnx_cvimodel_work/yolo26n.mlir
```

Output command:

```bash
model_transform \
  --model_name yolo26n \
  --model_def models/yolo26n.onnx \
  --input_shapes '[[1,3,640,640]]' \
  --mean 0.0,0.0,0.0 \
  --scale 0.0039216,0.0039216,0.0039216 \
  --keep_aspect_ratio \
  --pixel_format rgb \
  --output_names /model.23/one2one_cv2.0/one2one_cv2.0.2/Conv_output_0,/model.23/one2one_cv3.0/one2one_cv3.0.2/Conv_output_0,/model.23/one2one_cv2.1/one2one_cv2.1.2/Conv_output_0,/model.23/one2one_cv3.1/one2one_cv3.1.2/Conv_output_0,/model.23/one2one_cv2.2/one2one_cv2.2.2/Conv_output_0,/model.23/one2one_cv3.2/one2one_cv3.2.2/Conv_output_0 \
  --test_input /app/default_dataset/000000179487.jpg \
  --test_result yolo26n_top_outputs.npz \
  --mlir /tmp/onnx_cvimodel_work/yolo26n.mlir
```

Before running this command, create the output directory inside the container:

```bash
mkdir -p /tmp/onnx_cvimodel_work
```

HanJammer's first run confirmed the YOLO26 `output_names` issue is fixed: TPU-MLIR no longer failed on missing tensor names. The first attempt failed only because `/tmp/onnx_cvimodel_work` did not exist. After creating the directory, `model_transform` completed successfully: `npz compare PASSED`, producing `final_opt.onnx`, `yolo26n_in_f32.npz`, `yolo26n_top_outputs.npz`, and MLIR artifacts under `/tmp/onnx_cvimodel_work`. This has not been run on the BORG9 node because `model_transform`/`tpu_mlir` is not installed locally and Docker is not currently available there.

## `yolo26n-seg.onnx`

Local file size: about 11 MiB.

ONNX metadata:

- IR version: `7`
- Opset: `ai.onnx:12`
- Input: `images [1,3,640,640]`
- Graph outputs:
  - `output0 [1,300,38]`
  - `output1 [1,32,160,160]`

The detection branch has the same `one2one_cv2`/`one2one_cv3` tensors as detection, but segmentation also includes `one2one_cv4.*` mask coefficient branches and a proto output path. Treat the generated six-output command as incomplete for real segmentation deployment until the exact reCamera/SSCMA segmentation output contract is confirmed.

## Deployment caution

Do not overwrite `/userdata/Models/model.cvimodel` on the reCamera until a cvimodel has been converted and its runtime metadata/postprocessing compatibility has been verified. Active factory runtime is YOLO11n-based and may not understand a YOLO26 pre-head output layout without matching postprocess support.
